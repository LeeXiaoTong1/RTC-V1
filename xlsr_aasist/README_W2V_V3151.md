# V3.15.1：让官方 Online 参与 TFCL，并减少训练等待

这一版继续使用 w2v-BERT 2.0、MultiConv 和现有分类器。从明确指定的 **V3.15 best_guarded** 接续；不加载 OmniASR，不安装 V3.16 环境，不覆盖历史脚本或检查点。

本次用户反馈：V3.15 best_weighted 官方 Clean/Noisy/Weighted 为 98.2366/91.5533/93.5583，best_guarded 为 98.1333/91.7059/93.6341。这说明本地 Weighted 最大值不能充分代表官方收益；并不证明现有保护规则普遍最优。V3.15.1 尚未完成真实服务器训练，也没有官方成绩。目标仍是 Weighted 超过 97，以下设计不能保证达到该目标。

## 训练关系与配比

每次更新仍取 16 个原始来源，构造 48 个完整音频视图。四组 EN-fake、EN-real、ZH-fake、ZH-real 的分类权重各 25%。

| 视图 | 来自哪里 | 主阶段分类权重 |
|---|---|---:|
| 官方 Online | 官方 Train 中已验证同源的通信录音 | 50% |
| 通信参照 | 同源 Offline 经过本次模拟通信，不加入额外噪声 | 10% |
| 含噪通信 | 同源 Offline 先加噪，再经过与参照相同的通信设置 | 40% |

前四分之一轮从 60/10/30 平滑过渡到 50/10/40。原始 Offline 仍用于生成匹配版本，但不再作为未经处理的直接分类输入。缺少官方 Online 配对的来源明确排除，数量、来源 ID、语言/真假分布和重复采样次数记录在 `sampling_epoch_*.json`；不会拿 Offline 冒充 Online。

“已验证同源”沿用固定的官方配对清单及原始波形哈希、标签、语言、完整时长和文件身份检查；不能仅凭相似文件名临时猜配对。

三视图只通过共享检测器各一次，同时形成两条辅助约束：

1. **官方 Online ↔ 模拟通信参照**：新增真实通信与模拟通信之间的联系。
2. **模拟通信参照 ↔ 含噪通信**：保留同通信参数下对噪声影响的约束。

两条边各占辅助目标的一半预算，总体仍是 `CE + ramp × (0.15 × 时间项 + 0.045 × 结构项)`。无效含噪配对不会取消有效 Online 配对，也不会把缺失边的预算自动分给另一条边。

时间项保留共享双向交叉注意力和完整有效轨迹，允许两端长度不同；结构项保持每个来源独立的通道 CKA，只有此分支池化到 201 格。官方 Online 的掩码独立，模拟端的已知缺失时刻不会误套到官方录音上。

辅助分支运行 FP32，分类/编码器仍使用原有 BF16 训练、FP32 评估。保留原始融合特征几何；没有把幅度归一化或额外损失包装成单纯的速度优化。两端都有梯度，注意力和投影只用于训练，提交模型架构不变。

## 训练范围

- 编码器最后 8 层更新，顶层学习率 `2e-7`，向前逐层乘 `0.8`。
- MultiConv 和第一分类层 `2e-6`，现有 adapter 和最终分类层 `5e-6`，TFCL 分支 `1e-4`。
- 默认最多 4 轮；至少两轮后，再按连续四次验证无历史指标或合格鲁棒性进展停止。严重退化及非有限数值仍可提前停止。
- 不额外加入语言对抗、硬样本排序损失或其他模型。学习率和新配比是工程起点，尚未证明最优。

## 验证和选择

完整历史固定 Dev 保持不变，仍每半轮验证。`Weighted = 0.3 × Online Clean + 0.7 × mean(Seen,Heldout)`，仅是本地代理指标。

额外诊断固定选择最多 512 个 Dev 原始来源，按语言和真假均衡，分成两个来源互不重复的处理面板：

- **选择面板约 256 条**：每半轮检查，不同机制分别输出，不能靠一个平均分掩盖某个机制的大幅退化。
- **最终核查面板约 256 条**：只计算起点和最终选定的 best_guarded，不参与候选排名、学习率和提前停止。若最终仍是起点，复用已核对哈希的起点预测。

新面板使用与训练留出的完整参数组合，**不声称引擎是全新平台**。历史 Heldout 中的 anlmdn 保持不变，本次训练不使用该引擎。两个新面板虽然来源互不重复，但这些原始来源仍在历史固定 Dev 中，因此最终核查也不是完全独立的来源泛化证明。

逐条件/语言输出 AP、AUC、EER、真假 Recall、macro F1、real@99%fake；JSON 另存混淆矩阵、分机制/噪声/强度结果和逐样本错误变化。小分组的 99% fake 指标存在量化粗糙问题，输出支持数及提示，不把它当作显著性检验。提交仍使用固定 `P(fake)>=0.5`。

`best_weighted` 继续只记录历史本地 Weighted 最大值。`best_guarded` 需要历史指标安全、额外面板改善、AUC 或匹配假音检出率的排序证据，同时防止机制或语言明显退化。通过条件后，用 `0.5×历史Weighted + 0.5×面板按机制平均F1` 排序；这是内部选择分数，**不是竞赛分数**。阈值完整记录在 config.json。

未产生合格提升时，明确保留指定的 V3.15 父模型作为 `starting_parent`；不会把 V3.12 或其他版本静默替换进来。`last` 始终可显式导出最后成功提交的状态。

## 提速与空间

旧增强配方每次出现通常不同，生成音频缓存命中有限，但每次写入仍有锁、目录扫描和落盘成本。新流程不保存生成音频或特征，保持确定性现场生成；原始波形和噪声仅用有限 RAM 缓存（默认每 worker 128 MiB + 64 MiB）。

训练 DataLoader 和进程跨半轮验证、轮次复用，预取两批。不同配对一起计算注意力，保留独立掩码、损失预算和 CKA。每来源仍三次 SSL 前向，没有额外教师前向，也没有缩短录音。

启动时用中位、长、最长 Train 来源实测物理批次和重计算开关，默认上限 18 条音频/10800 帧，逻辑批次不变。测试后恢复检测器、辅助层、Adam 动量/步数和随机状态；修复了非空 Adam 快照可能被共享张量污染的问题。显存预留 6 GiB，模型、精度、完整长度不随测速改变。

CPU 测试验证了固定随机条件下的批次分组损失、梯度和更新等价，不能保证真实随机训练轨迹、排行榜分数或 A100 加速倍率完全一致。日志区分 `compute_s/update` 和 `wait_s/update`，并打印 `TOTAL`、`CE`、加权时间项、加权 CKA、两类有效配对数和峰值分配/预留显存。

新音频/特征磁盘缓存为零。检查点仍只保存可训练部分、优化器和最多两个不同的精选候选，原子保存峰值预算不超过 20 GiB，另留 10 GiB 空闲；实际需求由启动检测器参数量计算。V3.15 及其 V3.12 基础依赖不能删除。新运行开始后，不要再压缩或修改已绑定的父模型文件。

## 部署与运行

在当前训练/导出结束后，用原来的 `sdd` 环境执行；没有新前端下载。

```bash
conda activate sdd
cd /home/ubuntu/LXT/RTC-w2v-improved
git pull --ff-only origin w2vbert2-balanced-robust-fast
cd xlsr_aasist
bash setup_w2v_v3151.sh

bash run_w2v_v3151.sh \
  --parent-run exp/w2v_v315_20261008_075905_5663 \
  --parent-checkpoint best_guarded \
  --upload-temp
```

这是新运行，不要对旧 V3.15 目录使用新版本的 `--resume`。父模型 SHA、具体 tag 和基线 Dev 重放会在开始时核对。

```bash
# 查看
bash watch_w2v_v3151.sh

# 只恢复新的 V3.15.1 运行
bash run_w2v_v3151.sh --resume exp/实际的_w2v_v3151_运行目录 --upload-temp

# 导出默认保护候选；目录、元数据明确记录选择及父模型
bash run_eval_w2v_v3151.sh --checkpoint best_guarded --upload-temp

# 可独立指定 best_weighted / last，绝不按目录名猜测
V3151_RUN=exp/实际的_w2v_v3151_运行目录 \
bash run_eval_w2v_v3151.sh --checkpoint last --upload-temp
```

V3.15 的原导出指令保持可用。本次不会启动 V3.16，不会清理或覆盖已提交的 V3.15 best。
