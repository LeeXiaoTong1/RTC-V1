# V5.4 实现与约定的逐项审核

日期：2026-10-22。被审核版本：`8819dcc`。依据：已确认的《接收端配对特征修正：基于 V5.3 的详细设计》，2026-10-21，第 3—13 节。修订配置标识：`repair_audit_revision=2`。

结论：原提交具备核心机制，但准备、梯度观测、功能验收和部分节省计算的约定没有完整实现。此前用“参数已保存、CPU 检查通过”概括整体完成度过于宽泛。本次明确修正这些缺口，保留实际实验尚未完成的边界。

## 原提交存在的差异与本次处理

| 原设计要求 | 原提交实际情况 | 本次修复及可核查产物 |
|---|---|---|
| 固定配对观察特征、margin 和参照漂移 | 主要是总体配对结果及通道 MSE；没有固定参照复测 | 固定 64 对，准备/预热结束/半程/末尾复测；记录原始与修正误差、Clean 漂移、margin、门控、纠正及新增错误 |
| 按条件、SNR、时长与 Train/Dev 分组 | 缺少多种分桶 | `pair_preflight.json`、`repair_summary.json` 补齐，并保留来源/配方详单 |
| 某组几乎缺席应停止 | 仅在某组完全为零时停止 | 有效配对不足 5% 阻止长训，报告组别与计数；不自动放大损失 |
| 共同基础增强与配方可追溯 | 仅核对来源和类别，PairInfo 不完整 | 增加共同增强/RTC 哈希、来源访问、槽位、长度、计划预算、对齐耗时及一致性检查 |
| 有效 Clean 帧估计固定尺度 | 只截取原始长度，没有排除滤波边界 | 排除输入处理边界/人工延长；仍不按 Noisy 可靠性筛 Clean |
| 重复前向与批次同伴检查 | 只有小模型单元测试 | 真实准备数据执行重复编码和不同同伴检查，记录绝对/相对差异；实际 GPU 数值仍由服务器报告 |
| 有限、分目标梯度审计 | 只有合并后梯度和参数更新范数 | 每 100 个成功步对一个 A 微批次分别记录 CE/LF/KD 的选定张量梯度；验证 LF 不穿入原始融合特征 |
| 无效配对跳过辅助图；先筛教师再运行学生 | 所有 A 配对都运行辅助 R 和 KD 后端 | 无效配对跳过辅助图；只有正确且置信度合格的教师才触发对应 Noisy 确定性后端 |
| 对齐共享一次下采样 | 延迟与局部可靠性各做一遍 | 两者共用 4 kHz 波形；与旧规则的数值等价性测试通过 |
| 小实验坡度受总预算限制 | KD 固定 200 步，小预算可能一直未到目标权重 | KD 坡度受剩余总步数限制；正常约 2229 步配方不变 |
| 减少常规同步 | 每次 LF 重复检查不变尺度，产生同步 | 在加载/首次使用检查固定尺度；梯度路径仍使用同一 buffer |
| 导出平均后检查修正及预测变化 | 只报告参数范数 | 从磁盘严格重载 final.pt，报告相同配对上的修正幅度、概率/margin、正确性变化 |
| 稳态测量含后端窗口与对齐耗时 | 只有时间、编码视图和显存 | 补后端窗口、worker 对齐时间、完整周期时间；明确不同计时口径 |
| 先做实际运行检查，再长训 | 原入口准备后直接训练 | 第一实际 batch 试走预热/联合路径；还原参数、Adam、RNG 和阶段；结果存 runtime_smoke.json |
| 历史困难来源的处理阶段复测 | 没有入口 | 独立 inspect_receiver 重放已记录配方，核对噪声来源和增益；中间视图不加入训练 |
| 困难样本重放的噪声身份 | 复用的旧日志器省略列表，噪声哈希/来源未写入 | V5.4 显式保存两类列表。V5.3 历史日志缺失的信息无法事后补造，复查报告明确标注核验范围 |
| 观测异常与提交边界 | CE 来源归属校验在 Adam 更新后，若校验失败会留下未记录的内存更新 | 将校验放到 Adam 提交前；失败回滚随机状态/缓冲区，权重与优化器尚未改变 |

## 核心模块与目标：逐项确认

| 项目 | 实际实现与证据 |
|---|---|
| 前端与输入 | 继承 V5.3 的完整输入策略、60 层 Omni 与全部历史 LoRA 前向；只开放末 16 层微调，没有换回 V4/w2v-BERT |
| V5.3 动态融合 | 继承已经训练的 conditioner；仍以输入统计调整层权重，没有重置成静态混合 |
| R | 2 个残差时序块，逐块核长 3/7/15 的 depthwise 卷积、256 维扩展；没有削成单层线性层 |
| Q 与旁路 | `[H,Hhat,Hhat-H]` 384 维输入，逐帧/通道 sigmoid；`Hstar=H+a*(Hhat-H)`；总计 197,184 个新可训练参数 |
| 初始化 | R 输出层为零，Q 初始为 0.1；初始有效帧及 AASIST logits 与加载的 V5.3 一致 |
| 分类 | Online/Clean-RTC/Noisy-RTC 均走同一个 R/Q/AASIST；CE 质量为 25%/25%/50%，内部四组均衡，原平滑/置信度项保留 |
| LF | 可靠帧 Huber，固定通道尺度；Clean 原始 H 和 Noisy 输入 H 都 detach，只更新 R；不约束最终融合结果全部靠近 Clean |
| KD | 同一模型确定性后端；Clean 停梯度且判对、标签概率 ≥0.90、比 Noisy 高 ≥0.02；温度 3，全局有效系数 0.02 |
| A/B 质量 | LF 系数 0.05、KD 系数 0.02；A 内乘 2，外层乘 0.5；逐来源、计划组预算归一化，无效来源不放大幸存者 |
| PCL | 删除模拟音素均值 PCL 及其方差项；保留官方 Online↔模拟 Clean-RTC 的原始特征 PCL，保持平台方差项原相对强度 |
| Dev | 已登记为训练身份的原 Dev Offline 可参与新配对，不依赖 CTC；原官方平台 PCL 资格范围没有扩大 |
| 长度与对齐 | 不裁正常语音；mask 区分 batch padding 和配对可靠帧；排除人工延长、滤波边界、强抑制；相对时延和双邻帧插值有正负/半帧测试 |
| 随机性 | LoRA dropout 全程 0；新 R/Q 无 BN/Dropout；CE 后端 dropout 保留，KD 确定性后端恢复原模式 |
| 阶段 | 前 min(200,ceil(总步数×0.1)) 仅 R/Q；随后旧末 16 层 LoRA/融合/后端开放；预热计入一个来源 epoch |
| 计算 | 普通步每视图一次 Omni 编码，Clean 特征复用 CE/LF/KD；新增小模块/后端和独立诊断开销有记录，不宣称零开销 |
| 保存、恢复、导出 | 严格保存完整 repair 参数及固定尺度；含 optimizer/scaler/RNG/游标；只迁移明确新增键，不使用宽松加载；新模块参与原锁定参数平均 |
| 困难样本 | 捕获实际 R/Q 后的 CE logits，逐视图质量与总 CE 对账；KD 的额外前向不会混入；观测 schema 标明 V5.4 |
| C0/C1/C2 | baseline / ce_only / paired 入口保留。C0 保留原模拟 PCL，C1/C2 共享新模块预热；不自动连跑三个实验 |

代码入口：[model.py](w2v_v54/model.py)、[repair.py](w2v_v54/repair.py)、[data.py](w2v_v54/data.py)、[objective.py](w2v_v54/objective.py)、[side.py](w2v_v54/side.py)、[train.py](w2v_v54/train.py)、[workflow.py](w2v_v54/workflow.py)。

## 验收证据和仍未完成的实验

44 项 CPU 回归全部通过（本次完整运行 44.906 秒），覆盖真实项目 AASIST、小型 Omni 形状编码器和真实训练器：结构尺寸、初始等价、梯度边界、A/B 系数、有效配对筛选、原对齐规则等价、固定诊断、参数平均后的实际预测、断点跨预热恢复、AMP 回滚、临时运行检查后的完全恢复，以及观测校验失败时不得提交更新。独立处理中间视图入口的命令行检查也通过。

以下边界不能用 CPU 通过来替代：

- 真实 3B Omni、BF16/FP16 和激活重算：本机没有服务器 GPU 与权重，未实际运行；入口已加入服务器首批实际检查，不把它说成已经通过。
- 真实 RTC 各条件下的低覆盖、数值差异与 50 步 GPU 用时：代码提供测量，尚无本轮实测结果。
- 未见来源的泛化收益、官方 Noisy F1 和 bootstrap 置信区间：尚无实验。V5.3 final 已使用 Train+Dev，固定监测集合只能诊断训练域行为。
- 原设计中的 V3.18.9 起点、严格来源隔离结构实验入口，本轮竞赛增量 CLI 尚未提供。当前 parent-run 明确仅接受已完成 V5.3；不能把当前 C0/C1/C2 或内部 Dev 包装成未见来源验证。这是未实施的独立实验路径，不是隐式支持的功能。

这些实验状态不影响对核心实现的核对，但限制了可以声称的效果：现在可以审计新监督是否覆盖来源、产生梯度、改变表示和实际预测；还不能声称它改善了真实比赛 Noisy 泛化。
