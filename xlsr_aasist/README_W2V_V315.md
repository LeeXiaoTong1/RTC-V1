# V3.15：让同一段声音经过噪声和通信处理后，仍然能够分清真假

起点是实际提交过的 **V3.12 last**：
`exp/w2v_v312_20261006_004830_7d2f/last.pt`，SHA256 为
`87d9aa636dcc64affd3c39b6ca3ed451645dcb6bd058f411d6089d78281f164c`。
用户反馈其官方 Weighted 为 **93.558**；本地固定 Dev Weighted 约 **96.2945**。
V3.14 没有得到可靠增益，所以这里直接从这个已验证起点继续训练。
目标仍是官方 Weighted 超过 97；本地指标和实现测试不能保证官方分数。

## 这次实际改变什么

V3.14 主要修改最后的决策和分类训练；V3.15 直接训练模型在处理前后保留真假判别信息。
每次选择一个原始 Train 来源，构造三个完整视图：

| 视图 | 音频来自哪里 | 主阶段分类损失占比 |
|---|---|---:|
| 普通视图 | 官方 Offline 或其已验证的官方 Online，按约 1:2 轮换 | 30% |
| 通信参照 | 原始语音通过本次抽取的通信设置，不加额外环境噪声 | 10% |
| 含噪通信 | 先加入环境干扰，再通过与参照相同的通信设置 | 60% |

缺少 Online 配对时，仅将普通视图换成 Offline，不改变含噪训练预算。
参照和含噪端共享处理参数、输入增益和可选的轻微早期反射；各自使用新建的处理状态，整段连续处理。
这允许噪声实际影响降噪、增益控制和编码的结果，而非仅在处理完成后加一层噪声。

每次参数更新固定 **16 个来源、48 个完整音频视图**。EN-fake、EN-real、ZH-fake、ZH-real 各 4 个来源、各占 25% 分类权重。
一个来源的两个难度等级按抽样次序交替，主阶段中等和较强干扰各约占 30% 分类预算。
前四分之一轮把普通/参照/含噪预算从 40/10/50 平滑过渡到 30/10/60，同时逐步开启一致性约束。
少数类会重复采样，来源池跨轮继续轮换；采样记录明确给出来源覆盖和重复次数，不宣称每轮遍历所有多数类来源。

## TFCL 如何接入

使用已有 w2v-BERT 层融合后的 **128 维逐帧特征**，位置在 MultiConv 卷积块之前。分类前向、完整录音输入和原有模型参数结构保留。

1. **双向时间对齐**：共享的多头交叉注意力分别用参照查找含噪端的信息、用含噪端查找参照的信息，再计算余弦损失。两侧都反向传播，不要求含噪端照抄一个被冻结的教师。
2. **通道结构一致性**：将完整有效时间轨迹池化到 201 个时间格，经共享投影计算通道 CKA。每个来源独立计算，再按来源预算求平均，避免改变物理批次后约束含义跟着变。
3. **真假监督保留**：三条音频都计算真实标签交叉熵。一致性只作为辅助目标，不能以“处理前后很像”替代真假检测。

主阶段目标为 `CE + 0.15 × 时间损失 + 0.045 × 结构损失`；两个辅助项在前四分之一轮线性升温。
分类和时间注意力使用整段有效帧，只有结构分支池化到 201 格；不会将分类输入截为四秒。
填充帧和已知短时丢失区域不参与对齐。不会根据模型是否已经判对来决定哪些配对获得学习机会。
辅助注意力和投影在导出时不使用，最终仍是一个检测模型，不需要语言标签或额外教师。

思路参考 [TFCL 论文](https://arxiv.org/abs/2607.17761) 和 [作者实现](https://github.com/JunXue-tech/TFCL)。
这不是论文逐字复现：原实现使用固定时长和不同前端维度；这里适配完整录音、128 维检测特征与可变物理批次。
论文的 EER 收益不能直接换算为本竞赛的 Weighted 收益。

## 增强范围与可复现性

- 处理机制按来源抽样约为：FFmpeg 降噪/增益/Opus 40%，真实 WebRTC APM/Opus 40%，轻度带宽限制/Opus 20%。这是本地处理机制覆盖，不声称完整重现任何官方平台、AEC 或丢包隐藏算法。
- 使用已有 Train 非语音噪声目录；连续噪声、短时事件、混合干扰各约三分之一。短噪声文件也可参与，不再要求每条噪声长于最长语音。
- 连续噪声用随机片段和交叠过渡衔接；事件按自然短片段放置。不会简单周期性硬循环一个短事件。
- 中等 SNR 15–30 dB，较强 SNR 5–15 dB；升温阶段更温和。能量在语音与噪声共同活跃处测量，稀疏事件使用局部 SNR；参照和含噪端共用防削波增益。
- 保留低概率短时衰减/完全静音：约 8% 的含噪视图触发一次局部衰减，其中约 35% 为静音；持续 20–100 ms，同时不超过整段的 2%。该区域排除出辅助对齐，整段仍参与分类。
- 来源哈希、出现次数、轮次和固定种子决定增强；中断恢复重新生成相同配方。录音不裁掉尾部，可选反射保留追加的短尾音。
- 记录噪声文件哈希、FFmpeg 二进制哈希/版本、WebRTC 版本与所有生成配方；环境或输入变更不会静默续训。

## 微调范围与轮数

| 参数 | 设置 |
|---|---|
| 编码器 | 仅最后 8 层更新，顶层学习率 `2e-7`，向前每层乘 `0.8` |
| MultiConv、池化、第一层分类 FC | `2e-6` |

| 训练长度 | 默认最多 4 轮；每半轮做固定 Dev 验证 |
| 普通早停 | 至少完成 1 轮，连续两次验证未取得足够 Weighted 进展就停止 |
| 异常保护 | 非有限值或相对起点下降超过 2 个百分点时提前结束/报错，保留已提交状态 |

取消 V3.14 的冻结向量提取和分类头重拟合。取消语言对抗、困难样本排序、额外教师及分数尺度损失。
可用 `--ce-only` 明确发起同数据、同计算预算的辅助损失关闭对照；默认只训练主方案，不自动多跑一个实验。

## A100 上的效率

逻辑批次 48 个视图不等于一次把 48 段录音全部放进显存。
默认物理上限 16 个音频、9600 个填充后特征帧；参照和含噪端必须同组，普通视图可以单独前向。
按完整长度分组，不截短较长音频，微批反向后立即释放图。

启动时使用 Train 的中等、长、最长来源测试两档物理批次和是否梯度重计算，选择留有至少 6 GiB 显存余量的最快实测组合。
测速会真实走前向、反向和 Adam，再恢复参数、优化器与全部随机状态；执行选择写入检查点关联的记录，恢复时不重新随意调批次。
训练打印 `compute_s/update` 和 `wait_s/update`，可以分清 GPU 计算慢还是增强供给慢。
进程间传递 NumPy，不传递 Torch storage 文件描述符，关闭 pin-memory，减少之前出现的 `ancdata`/pin-memory 故障。

相对于 V3.14 两视图，这版音频前向数量增加 50%，但不再提取全 Train 向量，也没有额外教师前向。
实际总耗时还包括增强和新验证面板，**不能预先保证和 V3.14 一样快**；以 A100 测速和前百步日志为准。
默认 `--workers 4`，需要手动限制时可用 `--microbatch 8 --frame-budget 4800 --no-autotune`。
`--cache-gib 0` 可关闭衍生音频落盘，配方和损失不变。

## 磁盘控制

只增量保存训练部分，冻结前端引用已有原始 checkpoint 和 V3.12 last。
不生成整轮音频目录，不生成逐帧或句子特征缓存。

- 滚动音频缓存硬上限 **6 GiB**，超出淘汰旧的衍生配对。缓存损坏会按相同配方重建。
- 一个原子事务保存 current、Adam、TFCL 与最多两个不同的最佳检测器；同一状态共用张量，不堆积每轮模型文件。
- 启动根据真实参数量估计旧/新检查点同时存在的峰值；默认要求新占用峰值不超过 20 GiB，并留 10 GiB 空闲余量。
- 按当前约 1.96 亿可训练参数量估计，检查点原子峰值约 8–9 GiB，加缓存及报告约 15 GiB，最终以 `V315_STORAGE` 输出为准。
- 你目前约 66 GB 空闲，应能容纳这一预算；启动仍以服务器实际空闲空间校验。
- V3.7 旧特征缓存只借用经过校验的来源清单；读取训练数据清单时不再加载 `x.npy/logits.npy`。

不自动批量删除旧实验。V3.12 last、原始 best、已有来源清单、固定 Dev 音频以及被引用的旧代码仍是依赖，不能直接清空。

## 验证、选择与报告

历史 Dev 完全保持原口径：Online Clean、Seen Noisy、Heldout Noisy，
`Weighted = 0.3 × Clean + 0.7 × mean(Seen,Heldout)`，固定阈值 0.5。
新增面板只用于额外保护和诊断，不混入这个 Weighted。

新增面板覆盖全部已验证 Dev Offline 来源，每个来源固定一个新处理配方。
其噪声完整录音与 Train 不重叠，通信参数组合在本轮 Train 中留出；这不等于证明历史基模型从未见过这些处理机制。
起点和整轮评估面板；半轮候选若有希望成为 guarded best，也先完成面板评估再入选。

保存逐条 Offline 和处理后 logits，按原始音频 SHA256 配对：
原本正确/处理后正确、原本正确/处理后错误、原本错误/处理后正确、两者都错。
报告分别给出处理视图数量与独立来源数量，避免把一个来源的多个版本误认为多条独立证据。
官方 Online 只有存在验证过的同源对应时才可参与这样的配对分析；本实现不猜测其对应关系。

保留三种独立选择：

| 导出选择 | 含义 |
|---|---|
| `best_guarded`（默认） | 固定 Dev 有增益且分类/新面板保护条件通过的最佳候选，否则回退实际 V3.12 last |
| `best_weighted` | 起点和所有已验证候选中，历史本地 Weighted 最高的状态 |
| `last` | 最后一次成功验证并提交保存的训练状态 |

guarded 的最小 Weighted 增益为 0.02 个百分点；Clean 最多下降 0.3、Noisy 最多下降 0.05、新面板最多下降 0.3 个百分点。
各语言/条件组 fake recall 最多下降 0.5、real recall 最多下降 1.5、AUC 最多下降 0.2、real@99%fake 最多下降 2 个百分点。
这些保护只影响 `best_guarded`，不会阻止 `best_weighted` 和 `last` 被保存；ROC 诊断也不会变成部署阈值。
只有官方 Train 产生梯度，不使用 Progress/Eval 调整参数或阈值。

## 部署与启动

```bash
conda activate sdd
cd /home/ubuntu/LXT/RTC-w2v-improved
git pull --ff-only origin w2vbert2-balanced-robust-fast
cd xlsr_aasist
bash setup_w2v_v315.sh
bash run_w2v_v315.sh \
  --source-run exp/w2v_v312_20261006_004830_7d2f \
  --upload-temp
```

setup 检查现有环境，运行真实 FFmpeg/WebRTC 的短音频预检和正确性测试，不重装 PyTorch/CUDA，不下载额外模型。
启动会先核对起点与数据、建立固定 Dev/Offline/新面板基准，再测速并训练。
新面板首次生成有额外开销，日志会注明所在阶段。

查看和恢复：

```bash
bash watch_w2v_v315.sh
bash show_w2v_v315.sh
bash run_w2v_v315.sh --resume exp/你的V3.15运行目录 --upload-temp
```

上一轮结果保留在终端，Ctrl+C 只关闭查看器。真正停止训练：

```bash
python -m w2v_v315.stop --apply
```

恢复保留原运行配置、增强配方和数值执行选择，只重放最后一次已提交验证后的步骤。
完成后导出（选用所需的一条）：

```bash
bash run_eval_w2v_v315.sh --checkpoint best_guarded --upload-temp
bash run_eval_w2v_v315.sh --checkpoint best_weighted --upload-temp
bash run_eval_w2v_v315.sh --checkpoint last --upload-temp
```

报告与 submission 分开生成。`submission_meta.json` 明确记录实际选择、是否回退、起点及检查点哈希。
临时上传失败时，ZIP 留在日志给出的服务器目录。

## 完成后的清理

先预览，再清理当前已完成版本自己的优化器、随机状态、训练用 TFCL 和滚动缓存：

```bash
python -m w2v_v315.cleanup --run "$(cat exp/.latest_v315_run)" --remove-cache
python -m w2v_v315.cleanup --run "$(cat exp/.latest_v315_run)" --remove-cache --apply
```

三种检测器导出仍保留，压缩后不再支持训练恢复。先写 `inference.pt`、切换完成记录、再删 `last.pt`，需要一定临时空间。
清理不删除任何原始语音、父版本 checkpoint、历史 best 或来源依赖。
