V3.19.1 — 处理机制扩展与困难条件训练的匹配对照
================================================

目的
----
从 V3.18.9 的已验证 best 出发，检验“训练未充分覆盖会破坏真假证据的
处理机制，且普通采样没有充分学习其中的困难来源”这一假设。

这是待验证的训练实验。实现正确、内部验证改善，都不等于 Progress Noisy
必然提升，更不能解释为“95% 概率超过当前最好成绩”。

入口与默认预算
--------------
在 Linux 训练服务器更新。当前训练应先正常结束或保存暂停。
以下分支从 v3.19-parent-best-metadg 分出，保留旧版本入口。

  cd /home/ubuntu/LXT/RTC-w2v-improved

三组都独立从同一个父 best 开始；后一组不会继承前一组的训练结果。
不重复头部预热，不自动推理/提交 Progress。

默认父目录：
  exp/w2v_v3189_20261016_183410_a437
使用 last.pt 容器内部记录的 best_model，预期 best 为 epoch_6_step_1403。
保留父目录和 last.pt，不要在实验过程中继续改写父实验。

可在首次启动时指定 --parent-run /绝对路径、--epochs 2、--seed 319102、
--workers N 等。--epochs 表示每组轮数。suite 锁定共同参数，恢复时不能改动。

运行目录、查看与暂停
--------------------
启动后显示 V3191_SUITE=...；该目录保存 suite.json、各组日志和最终报告。
关闭查看器 Ctrl+C 只退出查看，后台实验继续运行。

重新查看：
  tail -n 60 -F "$(cat exp/.latest_v3191_suite_log)"

安全暂停整个三组实验：
  python -m w2v_v3191.suite --stop-suite "$(cat exp/.latest_v3191_suite)"

等待日志出现 PAUSED_RUN / SUITE_PAUSED，再关机或切换代码。
请求在模型初始化或评估期间收到时，会在安全边界处理，可能需要等待。
即使当前组刚好完成，暂停请求也会阻止下一组启动。

恢复：
  bash run_w2v_v3191_suite.sh --resume-suite "$(cat exp/.latest_v3191_suite)"

恢复使用原目录、原参数、优化器、随机状态和下一更新位置。
已经完成的组跳过；失败或暂停的组恢复；不会悄悄新建同组训练。
有更新边界 checkpoint（每 200 步一次），安全暂停会立即另存边界。
强制杀进程最多重放最近保存点之后的步骤。

suite 使用独立的停止命令，不要用 stop_w2v_v3191.sh 操作 suite；
后者只用于下文的单组启动入口。

三组究竟比较什么
----------------
baseline：原有噪声/RTC机制，新增同源 Clean-RTC + Noisy-RTC 配对分类。
expanded：同样的配对分类，均衡选择新增处理机制。
hard：同样的机制集合、候选和训练预算，在一半 Noisy 来源上做困难选择；
      其余保留普通选择。困难选择只重分配机制，保留普通选择的机制计数。

重要：baseline 已使用新的配对分类方式，不等于完全复刻历史 V3.18.9。
父 best 是第 0 轮参照；三组之间才用于区分新增机制和困难选择的贡献。
“是否仅配对 CE 就有用”可由 baseline 相对父 best 的变化观察，
但这也同时包含续训与选模协议变化，不能当作严格的单因素因果结论。

三组使用同一套 4 组候选配方，随后仅将选中一组用于反向传播。执行优化后，
baseline 在非诊断步骤只生成必选的第 0 组；expanded/hard 仍生成完整候选，
但仅 hard 对决定选择所需的 Noisy 候选评分。三组统一使用以下分类目标：
  L_CE = 0.25 * L_Online + 0.25 * L_Clean-RTC + 0.50 * L_Noisy-RTC
每个 L 先在 EN-fake、EN-real、ZH-fake、ZH-real 四组内按来源求均值，
再对四组等权平均。改变的是损失权重，不是抽样数量或 batch 大小。
Noisy 来源同时提供配对 Clean-RTC，因此两者合计占 75%；官方 Online
来源占 25%。不再声称两类来源总权重相同，也不再沿用旧版八组 CE 等权。
总 CE 系数仍为 1；微批次切分和四类样本数量不会改变这些比例。
A/B 两侧分类等权；只在 A 侧保留继承的双 PCL。
没有虚拟参数更新、MLDG、XEUS、新 KL 或新分类器。

2026-10-20 分类权重更新
---------------------
旧分配为 Online 50%、Clean-RTC 25%、Noisy 25%；新分配由用户明确指定为
Noisy 50%、Online 25%、Clean-RTC 25%。PCL 系数、采样和处理配方均未修改。
新配置、步骤日志、suite 清单和导出元数据都保存 classification_ce_weights。
启动时会显示 [Objective] CE: Noisy=50%, official Online=25%, Clean-RTC=25%。
训练统计分成 online / clean_rtc / noisy，修复 Clean-RTC 被混入 Noisy 的问题。
同预算组间比较会拒绝分类权重不一致的实验。

这是新的训练目标：已启动的旧比例实验不能用 --resume / --resume-suite
悄悄切换目标。请保留旧结果，在无任务运行时更新代码，并按上方首次启动
命令从原 V3.18.9 best 新建实验；新目标的实验仍支持原样暂停与恢复。
默认仍为每组 2 轮、共 3 组，未增加训练或候选编码次数。
此前审计的 PCL 梯度诊断开关、丢包连续长度问题不属于本次权重更新。

2026-10-20 执行效率更新（仍为 V3.19.1）
--------------------------------------
原实现每步让三个组都额外编码 24×4×2=192 个候选视图。baseline 固定选 0，
expanded 通过来源哈希和质量门控选择；两者都不需要模型评分来决定训练输入。

现在普通步骤：
  baseline：候选评分 0；不生成不参与训练的三种额外接收端处理。
  expanded：候选评分 0；保留质量门控和相同的均衡选择。
  hard：只评分困难来源中符合固定机制配额、通过质量检查的 Noisy 候选；
        默认 12 条困难来源、各 3 个可行替代，通常 36 个视图。
        不为未参与困难选择的来源评分，也不为 Clean 诊断分数编码。

每轮第 1、201、401……步仍执行完整候选诊断，baseline 在这些步骤也恢复
完整生成。缺失的分数写 null，并标明观测数量；不把“没有测”记录成零错误。
GPU 分数合并成一次小规模回读。日志增加 score_views、score、compute、wait，
ETA 改用本次会话最近最多 50 步，避免更新前的慢步骤长期拖高预计时间。

正式 CE 音频、50/25/25 权重、PCL、来源/更新预算、学习率、模型结构均保留。
公平对照约束的是实际训练曝光和更新预算；困难挖掘的额外计算单独如实记录。
候选评分的物理批形状会变化；CPU 测试检查选择、参数、Adam 和随机状态一致，
真实 CUDA 吞吐与浮点数值仍以服务器为准，不承诺固定提速比例或更高检测分数。

可在当前轮中途保存后更新，不需要重新训练已有步骤：

  # 在 xlsr_aasist 目录；退出日志查看器后执行，Ctrl+C 查看器本身不停止训练
  python -m w2v_v3191.suite --stop-suite "$(cat exp/.latest_v3191_suite)"

等待日志出现 PAUSED_RUN / SUITE_PAUSED，确认后台保存完成，再执行：

  cd /home/ubuntu/LXT/RTC-w2v-improved
  git pull --ff-only origin v3.19.1-robust-conditions
  cd xlsr_aasist
  bash run_w2v_v3191_suite.sh --resume-suite "$(cat exp/.latest_v3191_suite)"

单组任务则使用 stop_w2v_v3191.sh，随后 run_w2v_v3191.sh --resume 原运行目录。
只允许从已知的 50/25/25 版本 fe56b05 的精确代码哈希进行这次执行升级；
未列入白名单的源码变化、配置变化或其他损失比例仍拒绝恢复。
保留原 config.json 与 checkpoint identity，不重写权重、Adam、随机状态或
采样游标。execution_policy.json 记录升级代码哈希和发生位置，并随报告打包。
如果修改受白名单保护的执行文件，需要同步更新并重新验证 execution_compat.json。

困难选择以真实类别的分数间隔为依据，评分使用 eval/no-grad，随后恢复
随机状态、模块模式和缓冲区。每个语言/真假单元的处理机制配额一致，
防止“Real 总是某种处理，Fake 总是另一种处理”的标签捷径。
质量失败导致的配额偏差、普通→困难错误翻转和实际编码量都会记录。

模型与优化器
------------
保留父 Omni 3B、多层融合 128 维、AASIST、窗口聚合与分类器。
保留父模型所有 60 层已学 LoRA 的作用；前 44 层冻结，只更新末 16 层。
冻结前层的 LoRA dropout 关闭。融合和后端继续更新。
PCL 使用父模型冻结的 Train 标度，不重新在 Dev 上拟合。
新 AdamW 不继承与旧 best 不对应的末轮动量；
学习率从父 best 所在轮的实际终点接续，默认在本组 2 轮内余弦衰减到一半。
每个逻辑任务只提交一次优化器更新；溢出会回滚并重试，不消耗成功更新预算。

新增机制及其边界
----------------
训练候选是在原有 RTC 输出上追加的处理：
  1. 频谱着色 FIR；
  2. 短时包重复/衰减；
  3. RNNoise 神经降噪。
原有输出作为候选 0 和质量失败的回退。

两条接收端视图共用处理参数、增益及包掩码，但独立初始化处理器状态。
这些是机制扰动，不能宣称复现了某个平台完整的收发链。
RNNoise 不是伪造检测教师，不参与推理，只处理允许的训练音频。
它可能改变细微伪造证据；能量/静音/裁剪检查只能排除明显损坏，
不能证明标签语义或全部伪造线索在处理后仍完整保留。

RNNoise 固定公共权重，首次自动下载约 0.3 MB：
  https://github.com/GregorR/rnnoise-models
  revision: 3eee541a283fd3b8f81b85b1748e3b9ccbefa04d
  file: somnolent-hogwash-2018-09-01/sh.rnnn
  SHA256: 70bb6685eb0c2a1d18e2918dca3fbfbd39317010b1802eb1b6ea73a92f3fdec0

FFmpeg 必须支持 arnndn。启动前验证权重、实际处理和延迟；不支持时明确报错，
不会静默跳过 RNNoise。下载失败可将该精确文件复制到服务器，
首次启动加 --rnnoise-model /绝对路径/sh.rnnn。
默认缓存 assets/v3191。没有额外下载语音样本。

PCL 排除包替换、强衰减、滤波边界、未验证对齐区间；
RNNoise 使用启动验证的延迟补偿，无法验证单条对齐时不强行施加 PCL。

验证与成功条件
--------------
使用共享 PCM 来源登记表，Train/Dev 和 Select/Audit 均按完整来源检查。
同内容不同容器的 PCM 关系必须贯通。如果既有划分本身存在 PCM 交叉，
会中止并给出原因，不自动改划分。

固定每个 Dev 来源的一条历史合成 Noisy，再生成：
  - 未在本轮训练中使用的 spectral_wiener 实现；
  - 未在本轮训练中使用的着色 + 包重复组合。
它们是处理实现/组合留出，不是官方未知 RTC 平台。
随机种子独立于训练种子，且三组共享完全相同的波形、顺序和哈希。

每轮只在 Select 来源推理。实际选模指标是各“机制×语言”Macro-F1 均值，
不是历史 Select80。默认新 best 必须同时满足：
  - 指标高于已选 best 至少 0.1 个百分点；
  - 官方 Clean Macro-F1 相对父 best 最多退步 0.2 个百分点；
  - 最差机制 Macro-F1 相对父 best 最多退步 0.2 个百分点；
  - EN-real、EN-fake、ZH-real、ZH-fake 召回各最多退步 0.5 个百分点。
最后三条相对固定父模型，不随每轮累积放宽；不过线则保留父 best。
这些容许差不是显著性检验，也不是保证任何子组完全不退步。

选择冻结后才评估最终 Audit，不能据 Audit 换 checkpoint 或调阈值。
历史 calibration 子集在本版仅用于最终 Audit，不再拟合分数。
V3.18.9 原报告的 best 校准是 identity（scale=1、bias=0）；
本版固定使用原始 P(Fake) 和 0.5 阈值，与该父起点评分规则相同。
两组分数被合并前，所有预算、父 checkpoint、处理波形都要匹配。

报告给出 expanded-baseline、hard-baseline、hard-expanded 的四组召回、
Macro-F1、错误翻转以及按完整来源聚类的 bootstrap 区间。
这是历史 Dev：它以前参与过开发，不能称为全新盲测。
95% 区间只反映这些固定来源下的统计不确定性，不代表未知测试集成功概率。
默认单训练种子仅作短程筛查，不能据此宣称跨种子稳定收益。

性能与报告
----------
候选评分增加前向计算，因此不要预期每轮快于原 V3.19。
候选不同时保留反向图；Clean-RTC 的编码供 CE/PCL 复用；
长度微批次、末 16 层激活重计算继续限制显存。
PCL 有效区间不同会带来实际编码量差异，三组并非逐操作相同 FLOPs。
worker 根据可用 CPU/RAM 和全部候选双视图的最坏队列大小配置，
不能只靠增加 worker 保证提速。启动日志会显示选择值和内存估计。

每组保留 last.pt（含 best_model）、steps.jsonl、来源覆盖和验证数据。
结束生成 suite/comparison.json、suite/report.zip。
传 --upload-temp 时打印 SUITE_REPORT_URL / REPORT_URL。
报告包含配置、来源与指标，不包含录音和模型权重。
上传失败可用同一 --resume-suite 重试，不重复已完成训练。
