# V3.16：可靠 Offline 参照的 TFCL

本版本落实“Offline 提供有条件参照，Online 独立分类，只约束可靠对应的判别信息”。继续使用 w2v-BERT 2.0 + MultiConv，以及现有分类前适配层；没有加入新的语言对抗、真假排序损失或分数校准头。

实现位于 `w2v_v316_tfcl/`。V3.15、V3.15.1 的代码和 checkpoint 恢复路径保持不变。以前的 OmniASR 实验模块 `w2v_v316/` 保留，启动、评估、查看及清理脚本另存为 `*_v316_omni.sh`，说明见 `README_W2V_V316_OMNI.md`。当前不下载或训练 OmniASR。

## 1. 是否重新训练

需要用新目标启动训练；不能把旧权重仅换一个推理脚本就称为完成新 TFCL。

默认 `--init pretrained`：从本地**官方原始 w2v-BERT 权重**初始化，重新初始化 MultiConv、层融合及检测分类部分，训练编码器最后 8 层与整个后端。前面的编码器保持冻结。这是重新训练检测任务，不是从随机参数重新预训练大型语音模型。

选择这个默认值，是为了让新训练摆脱历代检测微调的历史影响；这是一项需要实验验证的训练选择，不能据此断言旧模型已经被“训坏”。默认最多 4 轮，不会因为初期低于旧模型便在第一轮强制回退停止。已有 V3.15 best_guarded 用于比较和可明确识别的部署回退，不向默认训练模型注入其权重。

`--init parent`：精确继承指定 V3.15 checkpoint，重新建立优化器。它用于低成本接续，或固定起点检验 TFCL 本身。与原方案比较时，必须保持相同初始化、数据、更新次数和数值执行设置，不能把初始化收益记在 TFCL 名下。

| 设置 | 原始预训练初始化（默认） | V3.15 接续 |
|---|---:|---:|
| 最末编码器层初始 LR | 2e-5 | 2e-7 |
| MultiConv / 层融合 LR | 1e-4 | 2e-6 |
| 现有适配层 / 最终分类层 LR | 1e-4 | 5e-6 |
| 编码器逐层 LR 衰减 | 0.8 | 0.8 |
| 先仅训练后端 | 最多 200 次更新，且不超过一轮的 1/4 | 无 |
| 默认最多轮数 | 4，可显式修改 | 4，可显式修改 |

以上 LR 是工程初值，没有宣称最优。`initialization.json` 记录真实初始化来源和 SHA256。新运行不会继承旧 Adam 动量；`--resume` 才恢复同一次 V3.16 的模型、优化器、随机状态和更新位置。

启动参数修复：默认 `--epochs 4`，允许明确设置 `--epochs 8` 等正整数；默认值不再被误写为强制上限。`--workers` 必须 ≥0，`--microbatch` 必须 ≥3，`--frame-budget` 必须 ≥1。启动脚本会在创建后台任务前检查这些参数并打印实际数值；错误提示会指出具体参数和值。模型、TFCL 损失及默认训练预算未因此修改。旧报错发生在创建训练目录之前时，更新后直接重新启动，无需 `--resume`。

## 2. 三种输入与监督预算

每个逻辑 batch 抽 16 个来源，中英 × 真假四组各 4 个来源。每个来源最多三条**完整录音**：

| 输入 | 构造方式 | 来源内部的分类损失占比 |
|---|---|---:|
| Offline | 官方原始 Offline | 10% |
| Online | 经已有清单、原始音频 SHA256、来源 ID、语言与标签核验的官方 Online | 50% |
| Noisy | Offline 先混入噪声，再进行通信处理 | 40% |

取消原来的“模拟无噪 RTC 参照”。比例指 CE 损失预算，不是独立采样概率。每组总 CE 预算 25%，每个来源总预算相同。

没有官方 Online 的来源保留在来源池中，使用 Offline / Noisy 两条输入，分类预算归一为 20% / 80%。缺失的 Offline→Online 辅助边关闭，不把其辅助预算转给另一条边。每轮报告唯一来源覆盖、重复次数及缺配对数量；平衡抽样不等于每轮恰好遍历所有不同来源。

Online 的同源核验不证明其每一帧都能对应，因此还要做内容对齐。已有噪声、回声、增益、短时丢失和 ffmpeg / WebRTC / light 通信增强分布沿用，模拟音频按需在内存中生成。

## 3. 新 TFCL 如何工作

```text
同一来源：Offline             官方 Online             Offline + 噪声 → RTC
             │                    │                            │
             └────────── 共享 w2v-BERT + 检测后端 ──────────────┘
             │                    │                            │
          真实标签 CE           真实标签 CE                  真实标签 CE
             │
      分类正确且真实类别概率 ≥ 0.8
             │
             ├─ 冻结编码器前缀的内容特征 → 单调对应 / 可跳过 / 可靠性
             │
             └─ MultiConv 前的 128 维判别特征（停止梯度）
                    ├──→ Online：对应位置余弦约束 + 局部通道 CKA
                    └──→ Noisy： 对应位置余弦约束 + 局部通道 CKA
```

**参照有条件，分类始终执行。**同一个 0.8 门槛用于中英文和真假。Offline 判错或置信度不足时，关闭该来源的辅助参照；三种输入仍受真实标签监督。不会要求 Online / Noisy 已经判对才给予辅助学习。日志按四组记录参照通过率、实际配对数量和对齐覆盖率。

**对齐与判别分工。**从最后一个冻结的编码器层获取内容轨迹，对齐完全停止梯度。官方 Online 使用带跳过状态的单调序列匹配：仅匹配网格压缩到最多 192 个连续时间格，允许起止缺失及中间无对应内容；再回到原生帧并做局部修正。模拟 Noisy 使用已知输入采样时间映射，最多在相邻 2 帧内修正。默认余弦门槛 0.6，官方匹配另检查与远处候选的差距。它是启发式对应，不是音素级真值，也不是 Drop-DTW 的逐式复现。

**无对应内容不硬拉。**补齐、已知丢失、短音频重复扩展、追加回声尾部都不能作为辅助匹配内容。有效匹配少于 4 帧或覆盖不到处理端有效帧的 10% 时，这条辅助边跳过。分类仍使用完整录音；缺配对、低覆盖也不会放大其他配对的损失预算。

**判别重要性有上限。**计算 Offline 正确类别与另一类别的分差对融合特征的梯度，采用 `|特征 × 梯度|`，按有效元素均值归一、截断为最多 4 倍，再与 25% 均匀权重混合。权重停止梯度，不做二阶反传。这是当前模型的任务敏感性估计，可能仍包含来源捷径，不能称为已确认的“真正伪造痕迹”。

**单向时间项。**在可靠匹配的原生帧上比较带权余弦差异；差异小于 0.02 时不继续压缩。Offline 端停止辅助梯度，Online / Noisy 端可更新。共享模型仍会被分类梯度及处理端梯度改变，因此 Offline 并非永久固定的教师。

**局部结构项。**在相邻匹配组成的共同内容区间内，每最多 50 帧构造通道关系，至少 8 帧才计算 CKA。不跨已知空缺连接两个远处片段。采用停止梯度的重要性通道权重，最小化超出 0.02 容忍区间的 `1−CKA`。取消各自全段压到 201 格以及可学习的 `201→201` 时间投影。128 通道仍是学习表示，不是物理频带。

主方法的对齐与结构辅助分支**没有可训练参数**。最终推理只用一条待测音频，不需要 Offline、语言标签、配对音频或额外教师。

损失仍然只有 `CE + 0.15 × 时间项 + 0.045 × 结构项`，时间项在后端预热后用 1/4 轮渐进开启，结构项再延后 1/8 轮渐进开启。权重沿用量级，不据 loss 数字大小推断是否有效；同时记录实际加权项、融合特征上的梯度大小及梯度夹角。

## 4. 效率与磁盘

- 三视图共享检测器执行路径；保留同来源的完整视图进行累积。默认物理上限 18 条、10800 个填充帧，逻辑 batch 始终 16 个来源。长录音不会为了凑 batch 被裁掉。
- CUDA 启动时用实际长短 Train 来源测试物理 batch 与激活重算组合，预留 6 GiB 显存；测速后恢复模型、优化器和随机状态。这里的重算是激活重算，与模型 checkpoint 文件不同。
- 持久化数据工作进程；每个 worker 原音频 / 噪声 RAM 缓存默认 128 / 64 MiB。删除不用的模拟干净 RTC 处理调用；匹配矩阵只做一次 CPU 传输，避免逐匹配点同步。
- 判别重要性增加一次到融合特征的局部求导，对齐也有成本。不能承诺训练完全不增时；日志分开报告取数等待、更新耗时、重要性求导和对齐损失耗时。
- 新生成音频和特征**不写磁盘缓存**。只保存可训练部分、当前恢复状态与最多两个不同的选中模型，不复制冻结前缀。启动按参数量估算原子保存峰值，新产物预算上限 20 GiB，并要求额外保留 10 GiB；以服务器 `storage_budget.json` 为准。
- 不自动删除原始数据、官方预训练权重或历史 checkpoint 依赖。完成后可以显式压缩本次恢复文件，丢掉优化器但保留三种导出选择。

## 5. 如何判断效果

固定官方 Dev 的历史口径不变：`Weighted = 0.3 × Clean + 0.7 × Noisy`。同时打印 AP、AUC、EER、F1、真假 Recall 和固定 fake recall 的 real recall。

新增每次最多 256 个来源的 Offline 诊断，按原始 SHA256 与官方处理版、模拟处理版准确连接，统计“原来正确→处理后错误”“原来错误→处理后正确”。这是诊断，不作为新的训练标签或挑选阈值。

额外处理面板上限 512 个唯一来源：256 个用于选择，256 个只在最终选择结束后评估。最终面板使用本轮训练没有使用的 G.711 μ-law / A-law 机制；不会用于调学习率、早停或改选模型。**其来源录音仍属于历史 Dev，不是完全独立的新来源，也不能代表未知竞赛噪声。**旧 parent 是否接触过相关机制不作无依据断言。

保留独立 `best_weighted`、`best_guarded`、`last`。新初始化的 `best_weighted` 保存训练候选本身，即使它还没超过旧模型；`best_guarded` 只允许满足固定 Dev、额外面板和排序条件的候选替代旧 parent。最终审计两者，防止回退结果掩盖训练候选的失败。导出元数据明确写出选中的标签、SHA256 和是否回退。

四种同数据对照已经实现，不会自动给你启动四轮独立实验：

| `--tfcl` | 内容 |
|---|---|
| `ce` | 三视图分类，无一致性 |
| `original` | 原双向注意力及可学习时间投影形式，换成这两条新配对；不是原整套 V3.15 的完全复现 |
| `uniform` | 可靠单向参照、内容对齐、局部结构，均匀权重 |
| `weighted` | 上一项加停止梯度的判别重要性，默认 |

公平对照固定 `--init`、parent、seed、epochs 和物理执行参数，并加 `--fixed-budget --no-autotune`。`--fixed-budget` 禁用基于指标的提前停止；非有限损失／梯度仍会中止。四种配置都按相同损失预算统计，不能仅比较各自最幸运的一次本地结果。

## 6. 部署和运行

在当前训练结束后更新代码。使用已有 `sdd` 环境，不安装新的 CUDA 栈。

```bash
conda activate sdd
cd /home/ubuntu/LXT/RTC-w2v-improved
git pull --ff-only origin w2vbert2-balanced-robust-fast
cd xlsr_aasist
bash setup_w2v_v316.sh

# 推荐的主运行：原始 SSL 初始化 + 新检测任务训练，最多 4 轮
bash run_w2v_v316.sh \
  --parent-run exp/w2v_v315_20261008_075905_5663 \
  --parent-checkpoint best_guarded \
  --init pretrained --tfcl weighted --epochs 4 --upload-temp
```

默认从历史配置的 `ssl_path` 读取官方原始模型。若那里只剩处理器而没有原始权重，启动会明确停止；用 `--ssl-path /实际官方w2v-BERT模型目录` 指定已有权重。不会悄悄改用旧检测 checkpoint，也不会自动下载模型。`--parent-run` 在默认模式里用于比较、回退与核验数据来源。

```bash
# 与旧方法比较时固定同一起点：将 --tfcl 换成四种模式之一
bash run_w2v_v316.sh \
  --parent-run exp/w2v_v315_20261008_075905_5663 \
  --parent-checkpoint best_guarded --init parent \
  --tfcl weighted --epochs 4 --fixed-budget --no-autotune --upload-temp

bash watch_w2v_v316.sh
bash show_w2v_v316.sh

# 训练中已自动执行固定 Dev 验证（每轮两次），无需另启验证进程。
# 以下是训练完成后，单独重跑带标签的 Dev；只写小体积结果文件。
bash run_validate_w2v_v316.sh --checkpoint best_guarded
bash run_validate_w2v_v316.sh --checkpoint best_weighted
bash run_validate_w2v_v316.sh --checkpoint last
# 可用 --run exp/实际运行目录 指定运行，用 --out /新的结果目录 保存重复验证。
# 打印 Clean/Noisy/Weighted、AP、AUC、EER、Recall、F1；不重新训练或改选模型。
# 若 DEV_BASELINE_FALLBACK=True，本次验证的是保留的历史父模型；不会冒称新模型。

# 恢复同一个新版本运行；不要拿 V3.15 的目录传给 --resume
bash run_w2v_v316.sh --resume exp/实际的w2v_v316_tfcl运行目录 --upload-temp

# 以下是对无标签 Progress 推理并生成比赛 submission，不是本地 Dev 验证。
# 默认指向最新 TFCL 运行；需已完成，也可设置 V316_TFCL_RUN 指定目录
bash run_eval_w2v_v316.sh --checkpoint best_guarded --upload-temp
# 查看训练候选本身时明确选择 best_weighted 或 last
bash run_eval_w2v_v316.sh --checkpoint best_weighted --upload-temp

# 完成后先预览；加 --apply 才丢弃优化器。之后不能恢复训练。
bash cleanup_w2v_v316.sh --run exp/实际的w2v_v316_tfcl运行目录
# bash cleanup_w2v_v316.sh --run exp/实际的w2v_v316_tfcl运行目录 --apply
```

Ctrl+C 只关闭查看器。确实需要停止本版本训练时，可运行 `python -m w2v_v316_tfcl.stop --apply`；只定位当前目录的新 TFCL 进程及子进程。最后一次验证后未提交的更新会在恢复时重放。

独立验证入口为增量文件，不改动现有训练模块。已有运行固定了启动时的代码哈希；安装这个入口时，可只取 `run_validate_w2v_v316.sh` 和 `w2v_v316_tfcl/validate.py` 两个新增文件，保留该运行的原始训练代码。独立验证需训练结束后执行，会复用相同的固定 Dev 数据、全长输入、FP32 推理及历史指标口径，输出目录默认在 `/home/ubuntu/LXT/temp/<运行名>_dev_<checkpoint>`，不生成音频或特征缓存、不重跑最终审计面板。

## 7. 验证范围与研究来源

本地测试覆盖真实小型 w2v-BERT 前后向、冻结边界、单向梯度、缺对应片段、原生全长批处理、缺 Online 数据、原始权重初始化、精确恢复、选中权重导出、测速回滚、原子保存失败与压缩后的导出。另实际检查 ffmpeg、light、G.711 两种编码路径的确定性及完整时长。Windows 环境缺少 Linux WebRTC 原生依赖，其真实预检由服务器 setup 执行。没有声称已完成 A100 实测或达到 97 分。

- [TFCL](https://arxiv.org/html/2607.17761v2)：时间与结构一致性的出发点。
- [Drop-DTW](https://papers.neurips.cc/paper_files/paper/2021/hash/729c68884bd359ade15d5f163166738a-Abstract.html)：允许无对应元素的思想；本实现不是其原算法复现。
- [Attention Transfer](https://arxiv.org/abs/1612.03928)：任务相关关注信息的参考；本项目的 RTC 加权方式自行适配。
- [CKA](https://proceedings.mlr.press/v97/kornblith19a.html)：表示关系比较的度量依据。
- [Noise-robust synthetic speech detection distillation](https://arxiv.org/abs/2310.08869)：较少退化的条件辅助含噪检测的相关研究，不能直接套用其收益。
